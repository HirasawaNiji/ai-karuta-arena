# 本地音乐派对演示手册

首版包含手动画像、选曲公平检查、真实 1v1、多人同场和 4/8 人淘汰赛。无需 QQ 或 LLM Key。QQ 音乐场景为独立移动端原型，官方登录/曲库/分享未接入。

## 启动

使用 Node 24.21.0、pnpm 10.34.5 和 ffmpeg。首次执行 pnpm install --frozen-lockfile，再执行 pnpm build。将已授权曲包按 [素材提取脚本](../scripts/prepare-preview.py) 的 archive/output 位置参数（python scripts/prepare-preview.py 曲包.zip 提取目录）准备；路径必须与审计里的成员路径匹配。Windows PowerShell 示例（将占位路径替换为实际路径）：

~~~powershell
$env:AMP_MATERIAL_DIR = 'D:\MusicParty\audio'
$env:FFMPEG_PATH = 'D:\Tools\ffmpeg.exe'
$env:AMP_AUDIO_CACHE = 'D:\MusicParty\cache'
$env:PORT = '3210'
pnpm.cmd start
~~~

打开 http://127.0.0.1:3210 。启动会核验 105 个启用片段并缓存去元数据的 10 秒前奏；首次可能需要等待。启动和赛事补库均先转码到独立临时文件，成功后按源音频和转码结果的哈希原子发布到不可覆盖的文件，相同内容经比对后复用，失败保留已发布片段，避免其他房间读到刷新中的半成品。缓存目录须支持同目录硬链接；旧版本文件不会在服务运行时自动删除，以保留已有房间的引用。未配置音频时仅能体验入场与画像，不会启用假音源。素材不随 Git 仓库分发。清单默认 docs/evidence/pjsk-intro-review.json；自定义清单用 AMP_REVIEWED_MATERIALS。启动失败先看终端的文件/哈希/ffmpeg 错误。

每名玩家使用独立浏览器配置或设备，不能用同一配置的普通标签页冒充两人。手机局域网访问需配置 HOST=0.0.0.0 及本机防火墙，实际 WebView/手机兼容性须现场核验。演示服务没有生产身份或持久化，重启会清空房间。普通局域网 HTTP 可能不支持自动复制；点击“复制房间码”后会显示手动复制入口，点选房间码并长按复制即可。

## 建议演示顺序

1. **入场与偏好（约 2 分钟）**：创建派对、复制房间码、好友加入；选择标签与 3–5 首熟悉歌曲，也展示“跳过，保留未知”。偏好用于选曲参考，不当作识别成绩。
2. **双人（约 5 分钟）**：默认快速 10 对 10，两人准备、各选 12/BAN 2、查看公平重评。必要时房主确认信息不足告警。双方确认，播放者手势开启共享音箱；展示抢己方牌、抢对方牌后交牌及结算。另可切换 15 对 15。
3. **多人（约 4 分钟）**：大厅切换多人同场，2–8 人准备，生成 12 题、每人 BAN 1 或跳过、补齐重评；展示正确 +1、错抢本题锁定和同分并列。仅房主播放。
4. **四人杯（约 10–15 分钟）**：切换淘汰赛，全员准备后创建 4 人杯。按 [D4 操作](d4-tournament.md) 完成两场半决赛及决赛，强调每场第一位选手的播放设备、淘汰房主仍能调度、冠军一致。
5. **结束与反馈（约 1 分钟）**：解释逐题反馈更新个人画像，赛事内选曲画像保持冻结。展示可选补库/明确允许重复的路径，避免把样本不足包装成公平通过。

时间为现场安排估计，选歌和抢牌速度会改变实际时长。八人七场可能耗尽未曝光曲目，按提示补库或明确允许跨场重复，不静默放行。

## 自动验证与现场验收

自动浏览器必须使用独立测试 Chrome 并在启动参数配置 --mute-audio，包含开启音箱时的提示音；不要静音系统或用户其他应用。静音验证仍检查音频请求、解码、WebAudio 状态和裁决链路。它不证明真人能凭听觉识别片段。

现场真人演示由参与者主动使用共享音箱；当前自动验证期间保持静音。现场还需核对触屏抢牌、前后台切换、音量及识曲体验；QQ WebView 真机另记结果。D2/D3/D4 自动证据分别见对应文档，不将自动点击当作真人验收。

完整范围逐项状态见 [第一版验收审计](first-demo-acceptance.md)；工程完成与真人验收分别记录。
