# D3 多人同场抢牌

沿用 D2 的启动方式与 105 首核验前奏。在大厅选择“多人同场抢牌”，2–8 人完成入场准备后进入听歌抢牌。房主生成 12 题，每人可 BAN 1 首或跳过；服务端补齐、重评并冻结最终题组。短库不可凭确认告警绕过，公平告警需房主明确确认。全员确认歌牌，房主手势启用共享音箱后开局。

每题第一名正确动作获得 1 分；错抢者本题锁定，其他人继续。10 秒无人抢中则跳过，题组内每首仅播放一次。最终按得分排序，同分并列（如 1、1、3），稳定 ID 只确定展示顺序。逐题范围反馈只在完整结束后原子写回，超时未答不等于错误。

多人引擎独立于经典 1v1，共用题库、画像、洗牌策略、可信会话、心跳和事件验证。客户端不能发送分数或身份，不能获取种子及未来题序；音频仅由房主请求当前去元数据片段。受理顺序决定正确抢牌归属，不声称解决互联网延迟公平。

局中加入者作为旁观成员等待下一局，不修改当前冻结参赛者及准备版本；不能抢牌、中断比赛或确认就绪。正式参赛者断线、后台、播放失败会中断，不提交正式排名。重置或完成后旁观成员可加入下一局。局中禁止切换玩法/规则或修改参赛者画像。

验证：三独立 Chrome 客户端使用真实曲包完成选曲、三个 BAN、最终 12 首确认、实际音频、抢牌、错抢与结算；三端均为 8/0/0 分，排名 1/2/2。房主 8 条歌曲反馈，两名好友各 1 条对应错抢题目反馈。自动点击只依据当前已返回音频的哈希映射可见歌名，非真人识曲。单元/HTTP 测试覆盖竞争只得一分、错抢锁定、并列、短库、过期版本、伪造字段、音频权限、晚加入和断线。最终构建 360/390/430px 无水平溢出；浏览器拦截下一题音频后两端中断，未作答好友画像版本仍为 1、歌曲证据为 0。证据见 [三客户端验证](evidence/d3-browser-validation.json)。本地全量 509 项中 508 项通过、1 项发生 loopback 连接超时；该 HTTP 文件单独重验 4 项均通过。最终 CI 结果见 PR。
