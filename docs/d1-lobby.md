# D1 入场、画像与房间

D1 提供独立的 React/Vite 音乐派对页面和单进程 Node 服务。无需 QQ/LLM Key；创建房间、好友加入、手动偏好、入场准备、选曲预评估和房主素材试听均为真实 HTTP/浏览器流程。没有复制 Karuta UI。

## 运行

使用仓库指定的 Node 24.21.0、pnpm 10.34.5：

~~~sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
~~~

打开 http://127.0.0.1:3210 。两个独立浏览器/无痕上下文分别创建和加入；同一浏览器资料的标签页共享成员会话。默认 HOST=127.0.0.1、PORT=3210；受控局域网演示可设置 HOST，当前不是公开生产部署。

服务端内存保存房间与画像，重启会清空；会话有效期 6 小时，演示限制 100 个房间、500 个会话、每房间 8 位成员。用户无需账户，QQ 官方身份、曲库、宿主播放和分享能力均未接入。平台边界位于 apps/web/src/platform.ts，当前只提供浏览器复制房间码和试听控制。

## 画像与准备

- ManualPreferenceSource 接受完整当前输入，记录服务端身份、时间和原始 heard/familiar/intro 枚举。取消选择会从当前画像撤回；这不把未选歌曲判成不认识。导入历史仍可通过原 buildPlayerProfile/normalizeEvidence 路径处理。
- onboarding-v1 标签默认 weight=0.8、confidence=0.4。未知素材的艺人/语言/曲风不会被自动猜测，因此这些标签不自动提升待核验歌曲的熟悉分。
- score-v2-manual 为自报提供 0.25/0.65/0.85 下限、0.6 置信度，放在原 base 与游戏判定之间。未指定录音的 intro 降为歌曲级 0.65；有范围的强识别只匹配当前录音/题段。具体范围优先，最新下调替换同范围旧值。score-v1 回归保持原行为。
- 服务端持有 party-runtime 的 createLobby。浏览器只发意图；身份来自 192-bit 随机会话的 HttpOnly、SameSite=Strict Cookie，不接受请求体中的 playerId/role。每人只修改自己的画像/准备，只有房主修改预设和发起评估。
- D1 使用 REST 意图 + SSE 状态通知。当前没有抢牌动作；D2 的时序敏感引擎通道另行接入，不声称 SSE 已实现游戏协议。
- 成员、画像、预设、断线/重连变化会清空准备和旧评估。刷新保留会话与画像，但要重新准备。lobbyReady 与最终 matchReady 分开；D1 的 matchReady 始终为 null，canStart 始终为 false。
- 预设来自 core 的 DUEL_PRESETS：默认每人选 12、BAN 2、起始 10，标准局选 18、BAN 3、起始 15。预评估候选目标分别为 24/36；不追加空牌。最终 BAN 后 20/30 张重评、冻结、音频就绪与正式开局属于 D2，不复用预评估当最终开局凭据。

## 素材试听

仓库只提交 D0 的元数据与哈希，不提交音频。默认显示 106 条待核验记录、0 条已核验可玩。待核验记录可用于歌曲级自报，但没有虚构的 intro Question，不能进入实际选曲。

在持有 D0 已审计曲包的机器上，准备本地试听文件：

~~~sh
python scripts/prepare-preview.py /path/to/jla-muca-pjsk-lite.zip /path/to/local-preview
~~~

随后设置 AMP_MATERIAL_DIR 为提取目录再运行 pnpm start。脚本校验整包 SHA256、逐文件大小和 SHA256，只提取审计清单中的音频；服务启动时再次检查文件哈希。可使用被忽略的 .local/ 目录，不要提交音频。

创建房间后，房主从大厅底部进入“素材试听核验”。播放器由用户点击启动；不自动播放，页面失去可见性会暂停，返回大厅也会停止试听。核验笔记可导出包含素材 ID、音频 SHA256 和时间的 JSON 草稿。草稿仍是 pending，不能自动晋升 verified；当前页面笔记不持久化，离开前应导出。

#11 后续据此逐条核验艺人、录音版本、原始片段起点、前奏语义、歌名映射与使用范围，再提交经过审查的正式素材清单。缺封面不阻止新产品的文字卡，但不消除录音/语义缺口。

## 验证与限制

自动化覆盖范围评分、最新下调、版本/片段隔离、v1 回归、服务端身份伪造、成员/画像/规则/连接失效、10/15 同源预设和可玩性过滤。服务端测试使用随机端口真实 HTTP/SSE；测试音频字节仅验证权限与 Range 协议，不伪装音乐素材。

浏览器证据见 docs/evidence/d1-browser.json。两个隔离 Chrome 上验证创建/加入、保存与跳过、独立准备、预评估、规则变化同步；桌面 1440px 和移动 360/390/430px 检查。真实 D0 音频可通过播放器点击播放并推进，Range 206，返回大厅停止，草稿可导出。

后台标签切换的自动化未能稳定触发 document.hidden，保留为限制；visibilitychange 暂停处理已实现，但不声称通过真机、系统后台或 QQ WebView 验收。CSS 使用安全区变量，桌面移动视口也不等于真机刘海屏测试。

D1 完成不代表素材语义审核、真实 1v1、多人与淘汰赛完成。D2 仍需修复 D0 交牌超时缺陷、实现冻结题组与事件版本/去重，再进行真人完整对局验收。
