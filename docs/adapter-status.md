# 数据与游戏适配器状态

当前核心保留 MockMusicSource、MockPartyHostAgent 与 MockKarutaGame，见 [M4](m4-party-runtime.md) 和 [M5](m5-demo.md)。可玩产品已实现 ManualPreferenceSource、真实 KarutaDuelFactory、MultiplayerFactory 和 4/8 人单淘汰组织器，见 [D2](d2-duel.md)、[D3](d3-multiplayer.md) 与 [D4](d4-tournament.md)。来源统一输出 RawUserMusicData，核心使用完整原始证据历史归并和画像；没有 QQ 专属模型或未经确认的私有接口调用。

## QQ 音乐：三种状态

| 状态 | 已知内容与处理 |
| --- | --- |
| 官方已确认 | 本仓库尚无经官方文档、授权账户及实际调用共同验证的数据/API/音频能力；此栏不代表任何接口已可用 |
| 等待确认 | 官方授权方式、允许读取的数据类别、字段/速率/撤销约定、音源使用范围与可演示资格。获得证据后再实现适配器和凭据配置 |
| 替代路径 | CLI 核心使用无账号、无音频的合成 Mock 数据；浏览器已提供手动标签/熟悉歌曲画像、105 首已确认前奏及双人/多人/单淘汰。无需 QQ 授权，启动见演示手册 |

不以“QQ 有版权”推导本仓库可以下载或分发音频。没有真实 QQ 登录、歌单导入或真实授权测试；环境变量示例不要求任何 QQ/LLM/数据库值。

## 主持与规则

Mock 主持只解释当前结构化告警与结果，没有 LLM 调用，没有情绪/疲劳推断，不制造房主确认。公平默认值为可复现规则基线，未校准真实胜率；熟悉度与可信度分别展示。权重/门槛的实际内容变更会使旧确认失效。

## Karuta 接入

独立的 Mock 回归每首一回合，正确 +1、错误/未答 0，事件有连续序号及冻结会话。它只验证运行时适配协议，不实现音频、网络抢牌或经典 1v1 规则。

现有 karuta-web 的核对记录在 [D0 引擎审计](karuta-engine-audit.md)，任务为 #11。D0 的 46 项引擎测试只代表原引擎基线。后续 D2 已核对冻结题组、question/recording/card 映射、105 首音频和事件适配，并完成两种局长的双浏览器自动结算；D3 三客户端及 D4 四客户端自动闭环另有证据。它们不替代现场真人听辨与 QQ WebView 真机验收。用户已授权复用现有项目内容；具体可播放材料应保留来源与使用范围记录。

已实现的 D1–D4 遵循 [初赛架构](preliminary-demo.md)：服务器生成可信 actor，玩家全部准备、素材可用和规则前置条件加入统一开局检查；1v1 使用核实后的经典规则，多人按抢牌规则，赛事对阵只消费一次结果并冻结赛事选曲画像。不得以当前 Mock 正确 +1 替换这些规则。

## 浏览器降级

当前 platform 层只提供浏览器房间码分享和试听控制，不伪造 QQ SDK 能力。安全上下文且权限允许时自动复制；普通局域网 HTTP 或权限拒绝时显示可选中的房间码，用户可手动复制。演示网络与操作步骤见 [完整手册](demo-walkthrough.md)。
