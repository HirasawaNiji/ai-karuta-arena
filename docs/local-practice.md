# 本地人机陪练

在独立本机服务中，一名真人即可完成音乐歌牌双人局。默认 10 对 10，也支持 15 对 15。电脑昵称为“电脑陪练（规则）”；本功能不使用 LLM，也不具备音频识别能力。

## 启动与停止

先按 [演示手册](demo-walkthrough.md) 安装依赖、构建并配置已核验的真实素材。然后执行：

```sh
pnpm build
pnpm practice
```

默认访问 http://127.0.0.1:3224 。AMP_MATERIAL_DIR、AMP_REVIEWED_MATERIALS、FFMPEG_PATH、AMP_AUDIO_CACHE 与正常演示相同；素材不随仓库分发。PORT 可指定其他空闲端口，HOST 仅允许 127.0.0.1 或 ::1。端口占用时应选择另一个端口，保留旧服务和房间。缺少核验素材时不能开局，不以测试音代替真实曲库。

终端 Ctrl+C 停止本次服务；关闭服务会清空该实例内存房间。若后台启动，应保留本次 PID 并仅停止该实例。普通 pnpm start 默认仍为真人对局，除非管理员明确设置 AMP_PRACTICE=1。

## 一个人怎么打

1. 填昵称并创建房间，电脑自动加入；填写音乐偏好或选择“暂时跳过，保留未知”。
2. 点击“我已完成入场，准备好了”，进入“03 听歌抢牌”，点击“开始选歌”。
3. 快速局选择 12 首、给电脑禁 2 首；标准局选 18 首、禁 3 首。电脑自动完成自己的操作。
4. 查看最终题组与熟悉度告警，按实际情况确认继续；点击“歌牌已就绪，启用共享音箱”，再点击“开始听歌”。电脑不会替你接受告警或启用音箱。
5. 听前奏、点击双方任意正确歌牌；抢到对方牌后交出自己的一张牌。电脑会自动交牌，所有抢牌、交牌和胜负仍由原服务端规则裁决。
6. 结算后点击“再来一局”；中途可主动中断后重开。退出房间即停止该房间陪练。

## 电脑行为与数据边界

- 电脑只在房主确认播放开始后计划抢答，等待 4–6 秒，有 25% 的题目不主动抢答。此参数是体验设定，不是识别正确率评估或胜率承诺。
- 到达反应时间后，规则脚本从服务端读取**当前题**的答案，再按普通动作契约出牌；不预读未来题序，不把答案映射发送到浏览器。电脑不模仿真人听觉。
- 选歌和禁歌从各自合法候选中随机选取；交牌约等待 0.8 秒。没有独立的延迟任务残留：每次操作核对当前局、题目和阶段，完成、中断、离线、重开或停止后旧计划失效。
- 专用陪练实例不进行任何玩家的对局画像反馈，避免将电脑脚本结果混入熟悉度证据；手动偏好仅用于当次选曲重评。结果只作练习展示，不是正式比赛成绩。
- 陪练房间拒绝其他玩家加入，也拒绝多人和赛事命令；正常真人服务的权限、心跳和反馈规则不变。此功能不是 #33 的整体 UI 改版。

## 验证

定向回归：pnpm exec vitest run tests/practice-opponent.test.ts tests/practice-server.test.ts 。覆盖两种局长、真人开局门槛、播放确认和反应延迟、跳题、自动交牌及整局结束、中断/重开、音频失败、离线、停止，以及 HTTP 入场隔离和正常真人房间。

浏览器验证须使用静音浏览器并检查实际音频请求、解码和对局结果；自动点击不等于真人听辨。提交 PR 时记录本次实际运行结果，不能将文档中的测试计划当作通过证据。

已启动真实素材陪练后，使用相同 AMP_AUDIO_CACHE / AMP_REVIEWED_MATERIALS 执行 `node scripts/check-practice-browser.mjs`。脚本使用本机 Chrome、独立配置与强制静音，创建测试房间，完成 10/15 张整局及中断重开、退出，确认电脑实际出牌且真人画像不变；每局结束退出测试房间，不操作已有用户房间。可用 AMP_PRACTICE_URL 指向另一个本机测试端口；截图与结果写入忽略目录 output/playwright/practice-59。测试助手依据当前音频哈希模拟真人出牌，不代表真人识曲验收。
