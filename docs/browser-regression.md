# 可重复静音浏览器回归

本套测试运行实际 React 构建、createApp HTTP/SSE 服务、WebAudio 解码及真实规则引擎。每位玩家使用独立 Chromium 上下文；全部浏览器强制 --mute-audio，并在操作前通过 CDP 核实实际启动参数。测试不会调整系统音量，也不需要 QQ/LLM Key。

## 运行

~~~sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test:browser
~~~

Linux CI 安装浏览器时使用 pnpm exec playwright install --with-deps chromium。本机已有 Chrome 时可设置 PLAYWRIGHT_CHANNEL=chrome（PowerShell：$env:PLAYWRIGHT_CHANNEL = 'chrome'）。使用项目指定 Node 24/pnpm 10；测试独占 127.0.0.1:3299，端口冲突时直接失败，不复用未知服务。

测试输出在被 Git 忽略的 output/playwright/，含 HTML 报告、失败截图/trace 和成功结果附件。用 pnpm exec playwright show-report output/playwright/report 查看；报告可能包含测试会话，不提交仓库。CI 保存报告 7 天。每次运行的合成音写入独立的 output/playwright/audio-UUID 目录；正常结束或测试失败时由 runner 清理，Windows 无需依赖服务收到退出信号。若整个 runner 被外部强制终止，可能保留该忽略目录。

## 验证内容

- 10 对 10、15 对 15：页面选歌、BAN、告警确认、音箱手势、当前音频请求/解码、抢牌、交牌、清空手牌结算及双方一致。
- 三人同场：真实 BAN/重评、非音箱成员无音频读取权限、状态无隐藏题目身份、错抢锁定、12 题计分、同分并列和三端一致。
- 四人/八人杯：分别完成三场/七场，验证八强赛、半决赛、决赛推进；上游胜者进入下游、淘汰房主继续调度，所有客户端看到同一冠军及完整赛程。逐场确认只有双方准备和持牌、旁观者没有抢牌控件；最终题组为 20 张，旧曝光歌曲不入选，赛前画像保持固定而个人反馈正常写入。
- 画像入场：标签与歌曲自报可独立保存，刷新后恢复；未指定录音的前奏自报保持歌曲级熟悉，下调/删除自报替换旧输入。
- 准备失效：修改局长或画像后清空旧准备、选曲和告警确认，重新准备与选歌后才可启动。
- 晚加入与断线：晚加入者等待下一局、当前歌牌不可抢；关闭参赛者页面使本局中断，原会话恢复后可与晚加入者共同重开并结算。
- 播放请求失败：双端中断、画像不增加识曲反馈；清除故障并重新确认后，新局能够完整结算。
- 心跳恢复：保持 SSE 打开，延迟真实心跳回复超过 15 秒；离线清空旧准备，过期回复返回 409，新挑战恢复在线且无需刷新，玩家重新准备后可开局。
- 赛事离开前台：模拟 visibilitychange 事件，验证中断发往携带 matchId/attempt 的赛事接口，不产生晋级或识曲反馈。此项是页面事件工程回归，不是真机后台验证。

八人七场用例的总时限为 7 分钟，四人和其他用例保持原有时限；没有延长单步等待或加入重试。

所有对局使用真实时钟。机器人只依据已经返回的当前音频字节 SHA-256 匹配可见歌名，并点击页面按钮；不读取未来题序、不写入分数、不绕过准备 API。只读状态用于断言与等待。浏览器回归保护真实 UI 与服务联动；领域/HTTP 回归仍由 pnpm test 执行。

## 夹具边界

素材为 tests/browser/materials.mjs 当场生成的 84 段不同频率 PCM 测试音，名称明确为“合成测试音”，使用范围仅为仓库工程回归。它不是音乐库、不是真人识曲，也不是 PJSK 曲包的替代验收。实际素材的哈希和自动浏览器证据继续见 D2/D3/D4 文档；真人/QQ WebView 真机体验如实单列，不再用等待这些反馈阻塞工程迭代。

UI 特化模型可在 #33 迭代后用本套回归发现真实流程退化；需要更新定位器时保留原有业务断言。#30 队战语义仍待人工确认，不由本任务处理。

## 生命周期回归发现的修复

#36 的模拟前后台事件在修复前复现：赛事复用的 DuelPanel 把中断发到 /api/duel/prepare，返回 HTTP 400，未携带赛事场次。现改为复用 prepareRequest，按当前模式选择接口，并在赛事请求中携带 matchId 和 attempt。相同浏览器用例修复后返回 200，本场进入 aborted，无胜者、无已完成场次和识曲反馈。普通双人仍使用原入口。

同一轮画像入场回归还发现初始化竞态：房间创建后表单提前出现，较慢的首次画像响应会覆盖用户刚选的标签/歌曲。测试延迟首次画像响应 2 秒稳定复现；入场改为先完成画像加载，再展示房间表单，避免覆盖快速输入。该延迟仅模拟请求延迟，不改变服务端游戏时钟。

#38 回归在修复前复现了持续离线：服务端只在 challenge 为空时发新心跳，过期但未清除的挑战使同一 SSE 永远拿不到新 token。现在 5 秒巡检会替换超过 15 秒的挑战；HTTP 仍拒绝旧 token，只有有效回复且 visible=true 才恢复在线，旧准备与确认不恢复。真实时钟静音浏览器验证延迟回复、原连接恢复和重新开局；HTTP 测试另覆盖 15 秒边界、重放与可见性。偶发本机初始 SSE 建连停滞和 Node 回环连接超时仍未定位，单独由 #39 跟进，不属于本修复结论。

如出现连接失败，使用[本地连接诊断](connection-diagnostics.md)区分接入与应用阶段；保留失败，不以重试或加大等待阈值替代定位。
